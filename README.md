# LLM 数据构造智能体

> 用一句中文自然语言描述你想要的测试数据，模型自动解析成 JSON Schema，再按约束批量生成。

一个最小的 FastAPI 服务：**自然语言 → JSON Schema → 结构化测试数据**。

适用场景：造接口测试的模拟数据、造压测数据、造演示用的假数据，省掉手写 Faker 脚本的功夫。

---

## 特性

- **自然语言转 Schema**：`"生成8个员工，部门从技术部/市场部/财务部里选，薪资5000-20000"` 直接可用
- **约束驱动生成**：支持 `enum` / `min` / `max` / `unique` / 固定值 `value` 五类约束
- **两种 Schema 风格都兼容**：约束平铺在字段上、或嵌套在 `constraints` 子对象里，都能正确解析
- **容错 JSON 解析**：模型偶尔会带 ` ```json ` 围栏或前后解释文字，自动剥离后再解析
- **上游异常明确化**：限流 → `429`，上游故障 → `502`，Schema 解析失败 → `422`，不再是裸的 `500 Internal Server Error`
- **自带端到端自检**：一条命令拉起服务、发真实请求、逐字段验收数据合规性

## 快速开始

### 1. 安装依赖

建议用虚拟环境，Python 3.10+（开发验证环境为 3.12.8）。

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate

pip install -r requirements.txt
```

### 2. 启动服务

```bash
uvicorn TestData:app --host 127.0.0.1 --port 8000 --reload
```

看到下面这行即启动成功：

```
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
```

> ⚠️ 请用 `uvicorn TestData:app` 启动。直接 `python TestData.py` 不会启动服务——文件里没有 `__main__` 入口，只会定义完 `app` 就静默退出。

### 3. 试一下

浏览器打开 **http://127.0.0.1:8000/docs**，在 `POST /api/generate_data` 上点 **Try it out**，填：

```json

```

也可以用命令行：

```bash

  -H "Content-Type: application/json" \
```

## API

### `POST /api/generate_data`

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `prompt` | string | 是 | 自然语言描述要生成的数据 |

```json
{"prompt": "生成8个中文员工，字段：姓名、部门、年龄、薪资，部门从技术部/市场部/财务部里选，薪资5000-20000"}
```

**响应体**

```json
{
  "schema": {
    "entity": "员工",
    "count": 8,
    "relation": "所属公司",
    "fields": [
      {"name": "姓名", "type": "string", "unique": true},
      {"name": "部门", "type": "string", "enum": ["技术部", "市场部", "财务部"]},
      {"name": "年龄", "type": "integer", "min": 22, "max": 60},
      {"name": "薪资", "type": "number", "min": 5000, "max": 20000}
    ]
  },
  "data": [
    {"姓名": "袁海燕", "部门": "技术部", "年龄": 41, "薪资": 9957},
    {"姓名": "徐浩", "部门": "市场部", "年龄": 39, "薪资": 14735}
  ]
}
```

`schema` 是模型对需求的理解，`data` 是按该 Schema 造出来的数据。**建议先看一眼 `schema` 再信 `data`** —— 模型的理解可能有偏差。

**错误码**

| 状态码 | 含义 | 处理方式 |
|---|---|---|
| `429` | 上游模型速率受限（免费额度打满） | 等一会儿重试，或升级配额；批量调用请加间隔 |
| `502` | 上游模型调用失败 | 检查网络 / base_url / 模型名 |
| `422` | 模型返回无法解析成 Schema | 重试；持续出现则调整 `sys_prompt` |

## 自检脚本

`test_e2e.py` 会自动完成：**拉起服务（自动挑空闲端口）→ 发真实请求 → 逐字段验收 → 关闭服务**。你不必手动开服务，也不用手动停。

```bash
python test_e2e.py
```

### 参数

| 参数 | 说明 |
|---|---|
| `--prompt` | 发给接口的自然语言需求，默认是「生成8个中文员工…」 |
| `--expect` | **对照提示词原话做硬校验**。格式 `字段=enum:值1,值2` 或 `字段=range:下限,上限`，多字段用 `;` 分隔 |
| `--runs` | 连续跑几次。跑 1 次验功能，跑 3~5 次看稳定性 |
| `--delay` | 两次请求的间隔秒数，避开免费额度限流。建议 `20` 起 |
| `--port` | 默认 `0` = 自动挑空闲端口，一般不用管 |
| `--timeout` | 单次请求超时秒数，默认 `90` |

### 常用示例

```bash
# 默认提示词，跑 1 次
python test_e2e.py

# 跑 3 次，间隔 20 秒（抓偶发失败 + 避限流）
python test_e2e.py --runs 3 --delay 20

# 换成自己的需求，并卡死金额范围
python test_e2e.py --prompt "生成5个中文订单，字段：订单号、客户、金额" --expect "金额=range:100,50000"
```

### 输出怎么看

```
✓ 服务已启动 http://127.0.0.1:54056  (pid=4792)
✓ [第 1 次] HTTP 200 | 字段=['姓名','部门','年龄','薪资'] | 条数=8/8
  样例: [{"姓名":"袁海燕","部门":"技术部","年龄":41,"薪资":9957}]
  ✓ 校验通过：枚举、类型、min/max、unique、条数均合规

结果：1/1 次全部通过
```

| 标记 | 含义 | 怎么办 |
|---|---|---|
| `✓` | 正常 | 不用管 |
| `⚠ HTTP 429 上游限流，本次跳过` | 免费额度打满 | 不用改代码；加 `--delay` 或稍后重试 |
| `✗ HTTP 500` | 代码或上游异常 | 脚本会自动打印服务端 traceback |
| `✗ 校验发现 N 处问题` | 数据不合规 | 每条问题都写明字段、序号、实际值 |

退出码 `0` 为全部通过，`1` 为存在未通过项，可直接接进 CI。

### 为什么必须带 `--expect`

脚本会对数据做**两层**校验：

1. **schema ↔ data 一致性**：拿模型返回的 schema 去验它自己的数据，检查条数、类型、枚举、上下限、唯一性。
2. **prompt ↔ data 硬校验**：拿**你在提示词里写死的约束**去验数据。

只有第 2 层能抓到真正的问题。因为模型偶尔会**漏输出约束**（比如忘了给「部门」写 `enum`），这时第 1 层自己和自己对得上，会判定「通过」，但数据其实是错的：

```
{"部门": "李欣", "年龄": 6424, "薪资": 897}     ← 部门成了人名、薪资低于下限，但它"通过"了
```

带上 `--expect "部门=enum:技术部,市场部,财务部;薪资=range:5000,20000"` 才会被拦下：

```
✗ schema 未输出「部门」的 enum（模型漏了约束），实际值样例 ['邓坤','张淑珍']
✗ #0 字段「部门」='邓坤' 不在预期枚举 ['技术部','市场部','财务部']
```

## 配置

全部集中放在 `TestData.py`：

- **接口地址与密钥**：文件顶部的 `client = OpenAI(...)`
- **模型名**：`nl2schema()` 内的 `model` 参数（当前为 `agnes-2.5-flash`）
- **Schema 解析规则**：`nl2schema()` 内的 `sys_prompt`。想让模型输出更稳定的约束，改这里比改代码更有效
- **生成规则**：`generate_by_schema()`

换其他 OpenAI 兼容服务（DeepSeek、通义、vLLM 等）时，只需改 `base_url` + `api_key` + `model` 三处。

## 依赖说明

`requirements.txt` 已锁定版本，其中一条**必须遵守**：

```
fastapi==0.115.12
starlette==0.41.3
```

FastAPI 0.115.x 要求 `starlette < 0.42`。如果放任 pip 装到 Starlette 1.x，`import fastapi` 会往 stderr 刷几十行：

```
StarletteDeprecationWarning: 'HTTP_422_UNPROCESSABLE_ENTITY' is deprecated.
Use 'HTTP_422_UNPROCESSABLE_CONTENT' instead.
```

在 PowerShell 里这些 stderr 会被包装成 `NativeCommandError`，把控制台刷崩甚至吞掉真实报错。锁定 `starlette==0.41.3` 即可消除。

## 已知限制

- **免费额度限流**：连续快速调用会撞 `429`。批量场景请在客户端加退避间隔，或升级配额。
- **模型可能漏写约束**：`sys_prompt` 已用固定键名 + 禁止嵌套 + 约束逐条落地的写法压住了大部分情况（实测从 2/5 失败降到 5/5 稳定），但不同模型/版本仍可能有波动。用 `--expect` 兜底验收。
- **未声明的字段由模型自行推断**：比如提示词里没写年龄范围，模型会自己给一个（如 18~65），生成值也随之变化。需要固定就写进提示词，并加 `--expect`。
- **不支持嵌套/关联数据**：`relation` 字段目前只作为描述返回，不会真正生成多表关联数据。
- **无鉴权、无并发控制**：默认只应在本地使用，不要直接暴露到公网。

## 安全提示

当前 `TestData.py` 将 API Key **直接写在源码第 10 行**。

如果这个仓库要推送到 GitHub，请注意：**公开仓库里的 Key 等同于已泄露**，任何人克隆即可消耗你的额度。若计划公开，建议先到服务商控制台吊销重建，再改为读取环境变量：

```python
import os
client = OpenAI(base_url="...", api_key=os.getenv("AGNES_API_KEY"))
```
